# Implementation Plans

Generated by the improve skill on 2026-11-10 against commit `1956ebb`. These
address the performance problem behind the 70 fps drag of a multi-card
selection, the latent problems that surface at document scale, and the NSH fork
work that removes the underlying costs. Each plan is self-contained; execute
in the order below unless the Depends on column says otherwise.

**Ground rules for every executor**

- Run `bun run check` and `bun run test` before you finish. Report host/manual
  evidence separately from automated evidence (standards §9).
- Branch from `main` as `advisor/NNN-<slug>`; Conventional Commits with a
  lower-case imperative subject and an explanatory body; **never** add AI
  attribution; do not push or open a PR.
- Frame budgets (≈10 ms app work / 16.7 ms frame / 50 ms input-to-feedback)
  are measured manually on the reference host (plan 001 documents how). They
  MUST NOT be asserted in CI (standards §8.2).
- Update your row's Status when done, then `./node_modules/.bin/vp fmt
  plans/README.md` (the formatter checks Markdown; `bun run check` fails on an
  unformatted table).
- Status values: TODO | IN PROGRESS | DONE | BLOCKED (one-line reason) |
  REJECTED (one-line rationale).

## Recommended waves

The table above is the dependency order. A practical way to work through it
without stalling on the large items:

1. **The visible problem** — 001, 002, 003, 004. These fix the 70 fps drag,
   the release/cancel stall, the six repeated geometry passes, and the idle
   wave timer that keeps test steps waiting 2 s. After 002 alone the group
   drag's JS per pointer move drops from ≈6 ms to ≈0.6 ms (optimized engine;
   ≈14 ms → sub-ms on the debug dev host). 004 restores fast test settling
   and honors Reduce Motion.
2. **Interaction quality at scale** — 005, 006, 007, 008. Rebuilds, composer
   blink, redundant wakeups, hit-test scans. 007 is the one that makes
   panning/zooming with a selection stop re-recording the connector layer
   every 80 ms.
3. **Measurement coverage** — 009 (needed before 011, 012, 014, 015, 016),
   then 010 (single-flight), 011 (read budget), 012 (gesture commit SQL).
4. **Latent costs** — 013 (blob: images), 014 (paint scale), 015 (search),
   016 (five small cleanups).
5. **NSH fork** — 017, 018, executed in `E:\code\mine\nsh-pr` with its own
   gates. These remove costs at the source but only help Flow after the pin
   in `src/native/Cargo.toml` is bumped to the new commit.

## Findings considered and rejected

Do not re-audit these; each was checked against the code at `1956ebb` and
found not worth a plan.

- **Move asset hashing/file I/O off the DB worker** — fires only on discrete
  user commands (≤4 picked images per upload, small mock SVGs per run, first
  display per asset); at most tens of ms of worker time once per upload.
- **Collapse `delete_nodes`' one query per historical batch** — a handful of
  indexed point queries per delete, never dominant next to that command's
  other per-node statements.
- **Auto-batch NSH's event dispatch** — an engine-level semantic change;
  explicit batching in the app's own commands (plan 002) is sufficient and
  keeps the batch/invariant mapping visible to reviewers.
- **A second, gesture-only connector canvas** — would cut the remaining full
  re-record during drags, but ADR 0005 specifies one shared canvas and the
  gain is unprototyped; plan 003 (box memo) is the cheap in-design part.
  Revisit only if the 009/011 measurements say it is still a problem.
- **Flag `composerPosition`/`inlinePosition` redundant evaluations** — ≈0.035
  ms per wake, 1 op / 0 mount items when nothing moves. Not a problem.
- **Search palette per-keystroke cost, page chrome ternaries, `<Each>`
  reconciliation on replaced arrays, `new Path2D` per icon draw, per-row
  closure creation** — each measured headless and found negligible (chrome
  ternaries get their own memo per function; keyed Each re-applying identical
  NodeSummary objects costs 190.4 ms vs 190.6 ms for fresh ones at N=2,000).
- **Trim `dataJson`/`settingsJson` from `NodeSummary`/viewport rows** —
  `node_detail.node` reuses `NodeSummary` and `composer-state.ts` reads
  `settingsJson`; splitting the type is a separate design decision. Plan 011
  caps row count / narrows far-endpoint reads instead; note it there as
  deferred.
- **Unbounded undo history (`History::LIMIT` 200)** — bounded by the ≤2,000
  selection; cloned once per command. Not worth a change.
- **Turn off the `FLOW_FPS` rAF meter in app code** — it is opt-in
  (`FLOW_FPS=1`) and documented as a measurement hazard in plan 001; no code
  change.
- **SQLite `mmap_size`, WAL checkpoint tuning, short-query LIKE fallback
  (recorded ~22 ms at 100k), per-input UPDATEs in `sync_inputs`/`reorder_inputs`** —
  minor or already fast.
- **Rank search hits before computing snippets (plan 015)** — the existing
  single FTS statement already lets SQLite defer `snippet()` to the rows the
  sorter returns. A two-stage rank-then-snippet adapter, exact on the same
  database, measured 5x slower at 100k because FTS5 re-runs `MATCH` for each
  `rowid IN` value: reference avg 270.25 / p95 293.04 ms vs rank-first
  avg 1361.41 / p95 1462.85 ms; an independent reviewer re-run measured
  279.22 / 304.80 vs 1399.23 / 1495.67 ms. `docs/plans/rust-core.md` records
  the phase diagnosis. Do not retry without a detail shape that does not
  re-run `MATCH`.
- **GPU-side cost, macOS/Linux/GPUI backends, touch/pinch** — out of audit
  scope, not verified either way.

## Things a maintainer should watch after landing

- Canvas hit testing now lives partly in `src/flow/resize-handles.ts`:
  `handleAtPoint` takes an optional cached `under` card, and the
  outside-card handle reach is `7 / camera.scale` world units. Keep the
  screen-point semantics (`handleAt`'s 7-point default) when changing it.
- Plan 007's per-id rect-signal map stays unbounded by design: `inlineId` can
  outlive `byId` (a double-click opens the inline editor before card
  selection, and the editor survives deselection), so `trimRectSignals` was
  skipped per the plan's STOP condition. Revisit together with the
  inline-editor lifecycle; do not delete signals while that reader can exist.
- A `NodeSummary`/`EdgeSummary` field added in the native crate must be added
  to `sameNode`/`sameEdge` in `src/flow/record-equality.ts` (plan 007); field-
  by-field comparison makes that a compile error rather than silent staleness.
- Any future camera write must go through `CanvasCamera`'s mutations (plan
  004 added the `moving` flag there); a future zoom animation needs the same
  settle behavior and Reduce Motion rule.
- `Animated.loop` with `resetBeforeIteration` was probed on the pinned NSH
  f0b4659. The plan-004 step-5 real-host paint check was re-run after the pin
  bump to `bc17f693`: at rest commits stay 0 and canvas stays ≈0.01 ms, and
  the comet sustains 240/240 frames with `over` 0% (11 cards, 30 connectors,
  17%, development host). Repeat it after any future pin bump.
- Plan 013's host regression tells headless from the Windows host by whether
  `app.screenshot()` resolves; `id:title-bar` is not a discriminator because
  headless with `platform: "windows"` renders it too. If headless ever gains
  screenshots, rework that branch. Its `ImageLoadProbe`/`imageProbeText` live
  in `FlowCard.tsx` because `FlowPage.tsx` hit the 500-code-line cap.
- Blob URL lifetime is page-scoped in `AssetUrls`; do not revoke on composer
  close (a preview can remount the same asset later), and keep one URL per
  content-addressed asset id.
- Plan 014's childless plate removes the border that used to inset the card
  body's absolute content, so body text and previews sit one **device** pixel
  nearer the card's top-left at every zoom; the decoration itself is
  pixel-identical at 100%. Do not "fix" that with a transparent border on the
  body container (it would re-add per-card paint) or a fractional
  `BODY_INSET` (it would blur text at some DPI scales) without measuring the
  renderer's border width first.
- Plan 014's detail tiers drop the shadow and body/status text below 0.35 and
  the title and previews below 0.2. The shadow is gated on `full`, so keep
  `flow/card-detail.ts`'s comments, the CHANGELOG and `docs/architecture.md`
  in step when thresholds move. The tier `computed` lives in `FlowCanvas` and
  is passed to every card as an accessor; reading `camera.scale` inside
  `FlowCard` would wake every card on every zoom tick.
- Plan 014 rounds `resizedRect`'s width/height on purpose; `sameRect`'s 0.01 pt
  tolerance in `src/flow/scene.ts` is larger than the rounding delta. A future
  tolerance tightening must revisit the plan's end-of-gesture commit STOP
  condition. Its real-host 100k evidence (92% is the nearest reachable
  full-tier zoom; the control jumps 92%→111%) is in the temp
  `measurements` directory, not the repo.
- Plan 016's `Document.isEmpty()` checks both nodes and edges, but an edge-only
  document is unreachable: `sea-orm-sync` enables `PRAGMA foreign_keys = ON`
  and the edge relations cascade. Keep both existence checks as defense in
  depth; `deleting_the_last_node_cascades_its_edges` fails if the FK/schema
  behavior changes, at which point the edge-only branch must be re-proven.
- Plan 016's schema version 4 partial indexes mirror the exact recovery
  filters (`nodes(document_id, status) WHERE status='running'` and
  `result_batches(status) WHERE status='running'`). Change them only with a
  new migration when those predicates change; the query-plan test asserts the
  index names.
- Plan 016's resize coalescing keeps one `pendingFitGeneration` token and the
  existing 80 ms drain; do not add a second timer or resolve joined callers
  before the newest automatic fit has been applied. Explicit fits clear the
  pending token; `userMoved()` invalidates it.
- Plan 016's `CanvasCamera` now publishes `view`, `scaleValue` and `changed()`
  in one batch through `publish()`. Any future camera mutation must route
  through it; a direct `view.set` would desynchronize `scaleView()` and the
  scale-only overlays. The grid wrapper is the one moving element; keep tile
  positions static and do not reintroduce per-tile camera reads.
- Plan 016 keeps the old preview reader only under `#[cfg(test)]`
  (`previews_reference` and `read_items_for_batches`); the composer's
  `read_batch` still reads every item and is not the preview path. The
  measured 2.5% preview gain is fixture-specific (every batch already has four
  items); the structural cap matters for larger batches and repeated assets.
- Plan 017 is merged into the NSH fork's `feat/windows-canvas-damage` at
  `921ef920`; Flow pins the branch head `bc17f693` as of `9d18110`. On the
  Windows development host with all 11 cards selected (30 connectors, 17%
  zoom, 240 Hz), the comet's canvas time fell 2.17 → 0.78 ms mean and
  over-budget frames 11.6% → 0%; paint fell 4.48 → 2.20 ms. These are
  sequential development-host observations, not thresholds. The paint-elision
  decision is read from the current recording values and must never be cached
  on the operation list. A configured shadow keeps a transparent foreground on the regular
  path: Direct2D's shadow effect takes the drawn shape's alpha, so the
  transparent case is invisible, but the predicate stays conservative rather
  than assuming it.
- The plan-017 slot index is used only for a drawing that outlives a frame
  (the first `set_args` after `set` keeps the full scans), caps at 4096 slots
  / 8192 paints, and falls back to full scans for slot-driven geometry, clips,
  `clearRect` and non-source-over composites. Do not shrink those fallbacks;
  the core `DamageScan` and the production `set_args` differential tests are
  the exactness contract. The gallery perf numbers are within noise because
  it does not draw Flow's comet; measure Flow after the pin bump rather than
  claiming a gallery speedup.
- NSH environment caveats from plan 017: the installed nightly reformats an
  untouched `nsh-core/src/core/list.rs`, so the all-workspace fmt check cannot
  pass on this toolchain (the changed file passes), and the shared 175 GB
  target cache / toolchain metadata makes `cargo test --workspace` fail in
  unrelated crates. Per-crate Windows tests, core damage tests, clippy and the
  release CLI gate pass; re-run the workspace gate in a clean target dir or
  CI.
- Plan 018 is merged into the NSH fork at `bc17f693`, which Flow pins as of
  `9d18110`. The off-damage skip is deliberately conservative: hosted items,
  filters/blend modes, and every shader view keep the whole-view path (the
  shader state is private, so even a non-backdrop shader is not optimized).
  Do not narrow that without a fixture that proves backdrop hydration.
- Plan 018's nine-patch outer shadow is deferred, not pending: Direct2D's
  blur is not byte-stable across destination shape extents, so sliced pixels
  cannot equal the whole bake. Keep the original bake; retry only with a
  shape-stable blur or an explicit tolerance decision.
- Plan 018's cache keeps current-frame decoration bitmaps via the
  `render::draw_into` `FrameGuard`; nested offscreen passes share the frame.
  The 96 MiB cap still wins when every entry is current. `BoxShape` geometry
  is lazy and forgotten after a multi-fill clip squares the corners; preserve
  those call counts in future fill changes.
- 017/018 reached the app through the separate pin bump `9d18110`, verified
  with `check`, `test`, `test:host`, the release 100k benchmark and the paired
  development-host comet measurement above.
